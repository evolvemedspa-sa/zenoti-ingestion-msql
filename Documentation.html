Getting started

Set up the local environment

Commands on this page run from the repository root in PowerShell. Install dependencies in the same Python environment that runs the scripts.

python -m venv .venv

Main SQL ingestion

& .\.venv\Scripts\python.exe -m pip install -r Zenoti\requirements.txt

HyperConnect

& .\.venv\Scripts\python.exe -m pip install -r Zenoti\zconnect\requirements.txt

PO / Transfer

& .\.venv\Scripts\python.exe -m pip install -r Zenoti\PO_Transfer\requirements.txt

Form exports

& .\.venv\Scripts\python.exe -m pip install -r Zenoti\guest_form_retrieve\requirements.txt
Runtime requirements

Install Microsoft ODBC Driver 18 for SQL workflows. Local browser login uses installed Google Chrome; HyperConnect and forms Dockerfiles bundle Playwright Chromium for Railway.

Configure Zenoti/.env. The PO service uses Zenoti/PO_Transfer/.env when present, otherwise the shared file. Process environment variables take precedence. Supply deployed settings through Railway Variables.

Transactions and reruns

The runner is a sequence of separate jobs. CSV-window cleanup commits before subsequent imports, and individual loaders commit separately. Earlier changes stay applied after a later child fails. Stock inventory appends snapshots on every run; repeating a snapshot can create duplicates.

The main log is Zenoti/logs/sql_ingestion_logs_<timestamp>.txt, with a best-effort Drive upload when configured. Detailed feedback replaces each fetched Center Name + Invoice No pair, while business KPI snapshots replace their parsed business date.

Workflow 02

HyperConnect report sync

Zenoti/zconnect/sync_hc.py captures a bearer token, passes HC_TOKEN to its child processes in memory, then pulls and loads the three reports enabled in its current run list.

& .\.venv\Scripts\python.exe Zenoti\zconnect\sync_hc.py
ReportData grainSQL refresh key
agent_metrics.pyAgent / center / dayagent_id + center_id + start_date + end_date + date

Select yesterday alone

& .\.venv\Scripts\python.exe Zenoti\zconnect\sync_hc.py --lookback 1

The default is seven completed days ending yesterday. Explicit date flags override the rolling window.

Keep CSVs without SQL ingestion

& .\.venv\Scripts\python.exe Zenoti\zconnect\sync_hc.py --no-ingest

CSVs remain in Zenoti/zconnect/. Use --only, --skip and --stop-on-error to control the enabled reports.

SQL ingestion replaces only the business keys present in the incoming payload, with delete and insert in one transaction. Keys absent from the pull remain in SQL. Successful ingestion removes its temporary CSV; failed ingestion keeps the file in the report folder and prints its path.

Location performance can also export organization metrics and a call-volume time series through --hc-extras. Those optional results are additional CSVs. The runner's Drive log upload is best-effort, including failed runs.

Workflow 03

Purchase and transfer orders

Zenoti/PO_Transfer/run_all.py selects one date window and fetches an Orders Listing snapshot. That same snapshot supplies the summary and both product-detail outputs.

OutputUsed scriptWrite behavior
Order summarypo_and_transfers_api.pyUpsert by ref_no; preserve existing summary IDs.

Transfer productstransfer_order.pyReplace product rows for fetched transfer orders.

Review the window and destinations

& .\.venv\Scripts\python.exe Zenoti\PO_Transfer\run_all.py --dry-run

Run the configured service

& .\.venv\Scripts\python.exe Zenoti\PO_Transfer\run_all.py

The default range is 31 completed calendar days ending yesterday in America/New_York. Ordered, raised, delivered and completed criteria are fetched, allowing an older order to refresh when its delivery changes.

All API windows complete before SQL loading starts. The summary and both detail outputs commit together after mapped values and row counts are checked. SQL failure rolls the shared transaction back; orders absent from the pull remain untouched.

Local snapshots, CSVs, load reports and checkpoints live under Zenoti/PO_Transfer/data/api_order_ingestion/<start>_to_<end>/. Railway removes temporary data after success or failure and retains its uploaded service log. --resume is intended for local backfills with retained checkpoints. A dry run avoids API/SQL work but still creates the runner log and can upload it.

Use --summary-only for the summary alone. Destination combinations are validated before fetching. See the PO / Transfer README for service-specific configuration and schema behavior.

The default --auth login captures a fresh admin session token using MINER_USER and MINER_PASSWORD. The token remains in memory. The regional endpoint requires the employee's Service Forms Report permission.

Authentication modeBehavior
login (default)Capture a fresh browser token.
webUse a supplied HC_TOKEN or a supported stored-token alternative.

Default scope is all centers and review/submission states. Options include --center-id, --csv, --host, --chunk-days and a JSON object supplied through --body-file. Field-mapping diagnostics make missing response fields visible.

Guest-level form answers

& .\.venv\Scripts\python.exe Zenoti\guest_form_retrieve\retrieve_guest_forms.py --start-date 2026-11-05 --end-date 2026-11-06

The API-key workflow fetches centers, requests appointments once per center and date window without page or size, and calls /v1/Guests/{guest_id}/Forms?version_no=0 once per unique guest. Image signatures are excluded. Identified duplicate appointments are removed while appointments with missing IDs are retained.

Understand the date selection

Guest-export dates select appointments. The answers are not associated with a specific service-form instance or filtered by form submission date.

Both commands write CSVs to the working directory, named zenoti_service_forms_<start>_<end>.csv and zenoti_guest_forms_<start>_<end>.csv by default. Guest retrieval records failures in a separate errors CSV, including runs where no appointments were recovered. Neither form exporter loads SQL.

Run the form regression checks

& .\.venv\Scripts\python.exe -m unittest discover -s Zenoti/guest_form_retrieve/tests -v

These checks use mocked network and browser calls.

Data interpretation

Dates and stock snapshots

Each workflow selects dates differently. Verify the logged window before comparing reports or scheduling a backfill.

WorkflowDate selectionInterpretation
Main CSV reportsSource filenames and report columns.Cleanup recognizes YYYY-MM-DD_to_YYYY-MM-DD for configured report prefixes.
HyperConnect runnerSeven completed days ending yesterday.--lookback 1 selects yesterday. The default Railway runner clock is UTC; call timestamps use UTC days.
PO / Transfer runner31 completed days ending yesterday in America/New_York.CLI boundaries override fixed service/shared dates, then the rolling range.
Guest birthday stepGuests created in the previous two calendar days, ending yesterday.Uses the process clock. --from / --to select creation dates, not birthday dates.
Service formsSeven days ago through today, unless CLI/shared dates are supplied.Both bounds inclusive; report requests send 00:00:00 through 23:59:59.
Guest form answersSame inclusive input defaults as service forms.Appointments use an exclusive end date, advanced one day. Windows contain at most seven days.

Stock inventory date columns

ColumnMeaning
date_inventorySnapshot business date parsed from the filename.
date_insertedStock load time in America/New_York.
ingestion_timestampThe same stock load time, where the target table has this column.

Accepted snapshot filenames contain YYYY-MM-DD, YYYY_MM_DD or YYYYMMDD, such as Current Stock_2026-07-31.csv. A filename without a recognized date produces null date_inventory; its load timestamp is a separate field.

Stock inventory accepts CSV, XLSX and XLSM inputs and can process a configured directory. Spreadsheets also need a compatible pandas Excel engine. All files in one run share its New York load timestamp. Repeating a snapshot appends another set of rows, so use snapshot date and insertion time to identify duplicate batches.

Operational checks

Troubleshooting

Browser login reports a missing module or missing credentials

Check the interpreter path printed in the error. Install the form or HyperConnect requirements into that same environment. Configure the shared login username and password in Zenoti/.env or process variables; local login also needs Google Chrome.

SQL connection or ODBC driver errors

Confirm Driver 18 is installed, connection settings are present, and the machine or service can reach SQL Server. Shared helpers can select an installed driver; several main loaders explicitly name Driver 18.

A request returns 401 or repeated 403 responses

Use a fresh browser login for bearer-backed reports. Service Forms also needs the employee's report permission and an accepted regional host. API-key workflows need a valid API key. Relevant bearer clients retry transient 403 throttling before reporting failure.

Guest-form requests appear slow

Read the immediate attempt logs and response timing. Requests default to 10-second connect and 30-second read timeouts per attempt. Total run time also includes retries, backoff and request pacing. Adjust the documented timeout settings as needed.

A CSV is open in Excel

Close the workbook before writing. Guest forms fall back to a timestamped filename on a permission error; service forms report the locked path so it can be closed and retried.

Stock snapshots have no business date or contain duplicate batches

Use a recognized snapshot date in the filename and distinguish it from the New York load time. Stock inventory appends every run; identify repeated loads by snapshot date and insertion time before choosing a batch to retain.

A main pipeline step prints SKIP

Review its local input or Drive folder and required filename pattern. Some loaders skip missing input. A successful runner exit does not confirm that every dataset had source files.

A HyperConnect CSV remains after a sync

With --no-ingest, retaining CSVs is intentional. With SQL ingestion enabled, a kept hand-off CSV indicates a failed load; the runner prints its location and the failing step. Fix the reported issue before replaying that file.
